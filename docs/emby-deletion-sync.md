# Emby 删除联动

## 范围

Emby 发送 `library.deleted` 后，MDCz 持久化通知并检查目标视频。文件缺失两次、间隔至少 5 秒，且媒体库身份正常时，才清理对应数据库记录。通知接收后至少等待 5 秒，通常总计约 10–14 秒，不包括正在执行的媒体任务和故障重试。

普通 `library.deleted` 通知仅支持使用 `move` 的库；复制 STRM 库的深度删除见下方扩展说明。Emby 与 MDCz 必须看到同样的输出路径。不做路径转换，目录级删除通知不会展开成目录清理。

MP 115 STRM 复制库的设计边界见 [115 STRM 删除联动实施方案](./115-strm-deletion-plan.md)，启用方式见[复制库扩展](#115-strm-复制库扩展)。

示例配置：

| 用途 | 路径 |
| --- | --- |
| MDCz 来源 | `/volume4/Media/AV/Normal` |
| MDCz 输出 | `/volume4/Media/AV/Link` |
| Emby 库路径 | `/volume4/Media/AV/Link` |

Docker 中也要挂载同样的路径；宿主机路径相同不能证明容器内路径相同。

## 启用

1. 发布前停止 MDCz，备份实际配置的 `MDCZ_DATABASE_PATH` 数据库（默认数据目录中的 `mdcz.sqlite`）。停止后再复制数据库，避免忽略 WAL 中尚未合并的修改。
2. 使用 `pnpm build:webui` 构建并按当前部署方式更新服务端和 WebUI。启动会自动应用新增迁移 `0008_emby_deletion.sql`；不需要手工执行 SQL，也不需要新环境变量。
3. 在设置 → 媒体服务器 → Emby → Emby 删除联动中，生成专用 Webhook 地址并立即复制。配置持久化的是密钥哈希，地址不能重新读取；丢失后轮换。
4. 填入 Emby Server ID，选择输出目录是 `/volume4/Media/AV/Link` 的库，选择“观察（只记录）”，保存。Server ID 可从实际 Emby 通知中的 `Server.Id` 确认；它不是 User ID。也可先保持关闭，在 Emby 配好地址并发送一条带 `Server.Id` 的通知，从运行日志的 EmbyDeletion 记录中读取服务器 ID。配置先创建输出目录中的 `.mdcz-library-id` 文件，用于识别正确挂载，不要删除该文件。
5. 在你的 Emby Webhooks 通知配置中，启用删除事件，使用 POST，目标为生成的地址，发送 JSON。Emby 必须能访问 URL 中的主机；网页访问地址是 localhost 时需要换成 NAS 的可访问主机和端口。当前 Emby 版本的菜单名称、插件需求以实际安装为准。
6. 用一部可丢弃的测试影片验证。通知需要 `Event`、`Date`、`Server.Id` 和 `Item.Id/Type/Path`，其中 `Event=library.deleted`、`Type=Movie`、`IsFolder` 不能为 true。缺字段、路径不允许、文件未登记等忽略原因写入运行日志，不会按标题或番号猜测。
7. 在观察模式看到“确认缺失，可清理记录”后，再切换为“自动清理记录”。切换配置会取消未完成的旧事件；用“核对已登记文件”提交新的核对，补清观察期间的缺失文件。

示意通知（时间需来自真实通知）：

```json
{
  "Event": "library.deleted",
  "Date": "2026-10-24T08:00:00.000Z",
  "Server": { "Id": "YOUR_EMBY_SERVER_ID" },
  "Item": {
    "Id": "12345",
    "Type": "Movie",
    "IsFolder": false,
    "Path": "/volume4/Media/AV/Link/ABC-123/ABC-123.mp4"
  }
}
```

## 清理规则

- 删除对应文件行与其文件级字幕资源行；影片还有其他版本时保留影片与公共资源。
- 最后一个文件删除时，删除影片、影片资源和关联 `movie_id` 的待处理项；同时清理目标路径对应的待处理项。
- 同番号没有其他影片、待处理项使用，且没有活动刮削/维护写入时，删除该番号的 `site_results`。
- 刷新影片库、待处理、首页统计与可用性缓存；图片变体缓存继续使用现有容量及过期回收策略，不在删除事务中全盘扫描缓存。
- 保留批量刮削/扫描历史与历史计数、下载器去重记录、媒体库、根目录、账号和全局设置。
- 不删除 `Normal` 中的文件，不删除视频或残留 NFO、海报、字幕等磁盘文件，不递归删除影片目录。

## 可靠性与排障

- 路由：`POST /api/webhooks/emby/<专用随机密钥>`。首次持久接收返回 202；重复通知返回 200；错误密钥返回 401；不合法 JSON 结构返回 400。202 只代表已入队，不代表已删除。
- 日志中不要记录完整 Webhook URL。MDCz 内置 HTTP 请求日志关闭；如果使用反向代理，必须为 `/api/webhooks/emby/` 隐藏完整请求 URI 或关闭该路由访问日志。专用密钥不能登录 WebUI 或访问其他自动化 API。
- 仅库内完整文件路径匹配成功才会清理。缺少路径、目录事件、未知文件、服务器不匹配及明显早于当前文件记录的旧事件会被忽略。事件时间与 MDCz 时间应同步；超过 60 秒的旧记录保护可能保守地跳过事件。
- 文件仍存在时保留记录。根目录无法访问、标记丢失、权限和 I/O 错误会重试，最多 8 次，之后显示“待检查”。不要在挂载失效时重建库标记。恢复挂载后可使用“核对已登记文件”重新提交核对。
- 未完成的刮削或运行/暂停中的维护任务会推迟清理；等待任务不消耗错误重试次数。重定位路径忙时也会推迟处理。
- 队列和去重结果保存在 SQLite，重启后继续执行。配置修改取消旧待处理事件；关闭联动即停止清理，无需媒体目录在线。
- “核对已登记文件”只遍历数据库已登记路径，不递归扫描磁盘，按已保存模式处理。服务离线期间的通知能否补发取决于 Emby，不保证漏通知自动恢复；恢复后手动核对。
- 已完成/忽略的接收记录保留 30 天；待处理和待检查记录保留。它们是联动运行记录，不属于影片库。
- 设置面板只显示待处理、待检查和观察预览，保留必要的重试入口；成功、普通忽略和联动关闭通知在运行日志中查看，不显示历史流水和累计成功/忽略计数。内部接收记录仍用于去重及恢复，不因界面隐藏而删除。

## 回滚

先在设置中关闭联动并停服，再回滚程序。关闭只停止后续清理，不恢复已删数据库记录。需要恢复时，在停服状态下恢复升级前备份，或重新登记现存影片。迁移只新增表，未修改历史迁移；恢复旧程序前优先恢复与旧程序配套的数据库备份。

## 115 STRM 复制库扩展

此扩展通过 MP 原生 `u115` 存储 API 处理已登记的复制 STRM。实测接口版本为 MoviePilot v3.1.9，认证使用 `X-API-KEY`。不需要 MP 桥接插件，也不向 MDCz 提供 115 Cookie。默认关闭；真实删除尚需用户环境中的观察与专用测试资源验收。

### 升级与配置

1. 停止 MDCz 并备份实际使用的数据库和数据目录。启动新版本会应用新增迁移 `0009_strm_cloud_deletion.sql`；已发布迁移保持不变，没有新增必需环境变量。构建仍使用 `pnpm build:webui`。
2. 确保 MP 生成目录为 `/volume4/Media/AV/Normal`，MDCz 来源也是 Normal、输出为 `/volume4/Media/AV/Link`，媒体库整理方式为 `copy`。不要让来源监控包含 Link。先暂停生成和整理，再处理既有目录迁移；程序不会替用户搬动真实媒体文件。
3. 在 Emby 删除联动面板中填写 MP 地址、API_TOKEN 和 115 允许根目录（例如 `/Media/AV`），点击“保存并验证 MP”。保存会只读验证认证、u115 和根目录身份。凭据保存于服务端数据目录的 `moviepilot-credentials/`，目录权限 0700、文件权限 0600，不回显；备份时一并保留。留空保留已存凭据。切换连接、账号或根目录后需重新保存并核验来源；有未完成深度删除时禁止更换连接。
4. 生成 MDCz 的专用 Webhook 地址，填写 Emby Server ID，选中复制媒体库，选择观察模式并保存。Normal 和 Link 均创建身份标记；挂载离线时不能重新创建标记绕过检查。
5. 点击“核验 STRM 来源关联”。只有 Normal 和 Link 都存在、内容哈希一致、来源在允许目录内且 pickcode 在完整云端列表中唯一匹配的文件才可关联。新发布的复制 STRM 会保存来源哈希；后台在没有媒体任务时自动补充新文件的云端关联。回填有 10,000 项及 1,000 个目录的扫描上限，超出、分页不完整或身份缺失均停止核验。
6. 在神医助手通知设置中，将实际删除用户的“媒体深度删除”通知直接发往 MDCz，使用 POST JSON、`Event=deep.delete`。AV 范围须从其他同步删除执行方排除；普通电影原有流程可保留。普通 `library.deleted` 和“核对已登记文件”不会为复制库生成云端删除授权。
7. 在观察模式核对最近事件中的 Link、Normal 来源列表、云端路径和 fileid。真实通知至少需要 `Date`、`Server.Id`、`Item.Id/Type/Path`；不接受目录或多版本推断。Description 中存在 `Mount Paths` 时与登记来源交叉核对，冲突则跳过。用户目前提供的 Emby 日志没有 JSON 请求体，不能据此认为实机通知协议已验收。
8. 在独立测试资源上完成观察后，才切换自动清理。已观察到的深度删除可以显式点击“重试未完成步骤”，重新核验后处理；不会仅因切换模式自动执行旧观察结果。真实云端删除需单独获得操作授权。

### 执行与恢复

- 执行阶段：核验身份 → 删除云端文件 → 确认云端结果 → 清理 Normal → 清理业务记录。队列保存文件版本、来源哈希、云端身份和成功响应确认，不依赖影片行的级联保留。
- 删除前从存储根逐级核对绑定目录的 ID、父子关系和路径，再从完整父目录列表核对目标 fileid、pickcode、类型及大小。单文件详情缺少 parent_fileid，不用于替代此检查。
- 其他已登记文件仍引用同一云端资源时，仅清理本次 Link 的业务记录，保留云端和全部来源关联。最后一个引用删除时，核验并处理此前保留的相关 Normal 来源。
- 云端必须明确返回 `success=true`，并通过健康查询和完整父目录复查后，才清理 Normal。响应丢失后目标不在原目录，仍保持“未确认”，不凭空认定删除成功，不按同名新 fileid 补删。
- Normal 清理先将目标移至同目录下以事件 ID 标记的 `.mdcz-delete-*` 临时路径，再核验哈希后移除。生成器替换原路径不会扩大删除范围；重启可继续检查已暂存的文件。若身份变化则保留替换文件并转入检查，不手工清空这些暂存文件。
- Normal 清理后再等待一轮，确认没有被生成器重建。有限次重试仍持续生成则显示待检查。持久抑制记录阻止监控、扫描和发布重新导入已删除资源；这些记录不会随影片删除而消失。同路径替换的新资源也会被保守阻止，需人工核对，可为新资源使用独立来源路径。
- 关闭停止后续副作用，保留深度删除进度；切换观察模式不继续已经开始的删除步骤。恢复自动清理后从原步骤继续，待检查事件可重试。修改连接或库绑定不能丢弃已经删除云端的未完成状态。

回滚前先关闭联动、导出或保留未完成事件状态并停服，再恢复配套程序和数据库备份。保留凭据目录和必要的未完成资源快照；回滚无法恢复已删除的云端视频，不通过将 copy 改回 move 回滚。
