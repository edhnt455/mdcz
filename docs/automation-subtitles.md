# 外挂字幕更新通知

字幕插件完成写盘后，使用 MDCz 自动化 API Key 提交通知：

```http
POST /api/automation/subtitles/updated
Authorization: Bearer mdcz_xxx
Content-Type: application/json

{
  "eventId": "b157bd22-055f-4b67-872f-22a02f312cff",
  "mediaPath": "/media/259LUXU-1573/259LUXU-1573.mp4",
  "subtitlePath": "/media/259LUXU-1573/259LUXU-1573.chs.srt",
  "language": "zh-CN"
}
```

两个路径使用媒体服务器视角；需要时在设置中配置自动化路径映射。影片必须已登记，字幕必须存在且符合现有同目录字幕匹配规则。STRM 影片传 `.strm` 文件路径。中文语言代码以 `zh` 或 `zh-` 开头，按回调提供的语言标记中文字幕。入队时绑定已登记文件的 ID，排队期间发生移动或重命名会跟随当前登记位置；绑定文件已删除则失败。无法识别的旧路径不会按番号猜测归属。

返回 `202` 和 `{ "taskId": "subtitle-update-…", "status": "queued" }`。同一个 `eventId` 重试必须携带相同字段，返回原有任务和当前状态；同一 ID 对应不同内容返回 `409`。任务持久化，重启后未完成的任务重新排队。

```http
GET /api/automation/subtitles/jobs/{taskId}
Authorization: Bearer mdcz_xxx
```

状态为 `queued`、`running`、`completed` 或 `failed`。成功结果包含 `metadataUpdated`、`badgeStatus`（`updated`、`unchanged`、`skipped`）和 `mediaServerNotified`；`warnings` 记录跳过及通知失败原因，`error` 记录任务失败原因。通知媒体服务器表示对所有启用的服务器发送成功，未配置时为 `false`。

任务查询同时返回 `stage`、`progress`、`attempts`、`notificationCount`、`createdAt`、`updatedAt` 和 `completedAt`。`stage` 为 `queued`、`scanning`、`downloading`、`rendering`、`publishing`、`notifying`、`completed`，分别对应等待、核验字幕、下载原图、裁剪及角标生成、写入 NFO/图片/记录、刷新媒体服务器、完成；失败时保留失败所在阶段。

启用角标时，MDCz 从已记录的图片来源重建图片并应用当前全部角标设置，来源不可用的图片保持原样并产生警告。字幕登记和 NFO 更新不依赖角标开关。手动裁剪功能沿用现有方式，字幕更新重建海报不保留此前的手动裁剪区域。

每次核验整部影片的字幕、NFO、目标图片和角标设置。结果未变化时，不下载原图、不重写文件或记录、不重复刷新媒体服务器；即使使用新的 `eventId` 也如此。字幕内容发生变化会请求刷新。图片来源暂不可用时，后续通知可以重新尝试生成角标；刷新失败时保留待通知状态，后续通知在结果不变时仅补发刷新。重发原 `eventId` 只查询原任务，要重新核验或补发通知需提交新事件。

## 批量通知与工作台

后台保持全局单条执行，不会因几百次回调同时下载和绘图。同一已登记影片在排队期间收到的新通知合并到同一任务，保留不同字幕与分段文件的通知；运行期间的新通知最多形成一个后续排队任务。每个 `eventId` 都保留独立回执，重试时继续返回它原来关联的 `taskId`。已完成任务收到新的 `eventId` 会重新核验。

字幕更新与刮削、维护、批量编辑、文件处理/删除、NFO 编辑、海报保存按影片协调。同一影片串行处理；共享输出目录的发布也串行处理。其他影片可以继续刮削或更新字幕。队首影片被占用时，先处理后续可执行的影片，同一影片仍按提交顺序执行。等待不增加尝试次数，列表和任务详情显示具体阻塞原因；暂停会话不会长期占用字幕任务的执行权。刮削、维护等其他任务之间原有的启动约束保持不变。

维护预览提交时会重新核验相关文件及登记记录。预览后若有字幕更新、编辑或文件变化，旧预览会明确失败并要求刷新，避免覆盖较新的结果。

进入「工作台 → 字幕与海报」查看数量统计、每页 50 条的任务列表、当前阶段和详情。失败后继续处理后续任务，失败项可点击「继续处理」重试；同影片已有活动任务时需先等待它完成。沿用网络层重试，不额外反复重试整个失败任务。图片跳过原因及媒体服务器通知警告显示在详情中。

点击「批量重试」可同时筛选多个错误类型，也可输入文件名或路径的一部分，例如输入 `741` 查找文件名包含该编号的任务。弹窗显示跨页命中数量，可逐条勾选或全选命中任务。要恢复历史「资源目标重复」错误，可清空错误类型选择，只勾选「资源目标重复」，然后全选命中任务并提交。提交后显示实际入队数量和因状态变化跳过的数量。同一影片的多条历史任务保留各自的回执并逐条执行，重试仍失败的任务可以继续查看错误详情。

历史错误已处理时，可点击「批量忽略」，使用相同的关键词和错误类型筛选，勾选或全选命中任务，再点击「忽略所选记录」。成功忽略的记录从工作台列表、失败数量及候选列表中移除。忽略操作仅记录清除时间，保留任务错误与通知回执；相同 eventId 查询仍返回原任务。提交时已变化的记录会跳过并计数。

发布需要同时更新服务端和 WebUI。升级前停止容器并备份整个持久化数据目录，替换镜像后启动；首次启动自动应用新增的 `0025_subtitle_resource_state` 迁移，保存文件绑定和核验指纹，保留已有任务、结果及 eventId 回执。历史排队任务首次执行时按确切路径绑定文件；旧路径已失效时明确失败。首次核验尚无指纹的影片可能重建图片，此后使用持久化指纹跳过未变化的结果。无新增环境变量、外部依赖或启动参数。

若回滚至旧版本，停止容器、恢复升级前的数据目录备份，再使用原镜像启动；仅替换镜像不能撤销数据库迁移，也不会恢复已修改的媒体文件。
