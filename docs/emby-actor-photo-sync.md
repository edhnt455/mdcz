# Emby 演员头像自动同步

MDCz 抓取并上传头像，Emby 保存人物主头像。上传完成后，Emby 展示头像不依赖 MDCz 运行、MDCz 缓存或电影目录中的 `.actors`。

## 配置与使用

1. 在“设置 → 媒体服务器 → Emby”填写服务地址、API Key 和必要的用户 ID。凭据需要能够读取人物并上传人物图片；权限不足时页面会显示错误。
2. 保持“自动同步演员头像”开启（默认开启），在“人物头像来源顺序”配置需要的来源。
3. 正常刮削或通过维护功能发布影片。MDCz 会通知 Emby 扫描，后台自动补全缺失头像，无需打开工具页。
4. 可选：填写“每日头像补查时间”，格式为 24 小时制 `HH:mm`（例如 `03:00`），每天补查一次全部演员；默认留空关闭，按 MDCz 服务所在时区执行。
5. 通过 Emby 设置中的“查看演员头像同步”进入人物工具页，查看待检查人数、同步进度、最近结果和失败原因，也可手动触发。

Emby/Jellyfin API 请求始终直连，不使用 MDCz 的全局代理，包括连接检查、人物读写、头像上传和入库扫描通知。外网头像来源的查询与图片下载仍遵循原有代理设置，无需为同步头像关闭代理。

默认头像来源顺序为本地 → gfriends（GitHub 图库）→ 官网 → AVBase，可在“人物头像来源顺序”调整。找到头像地址后停止查询后续来源。每位演员的头像查询日志按实际顺序显示各来源的“未找到头像”“找到头像”或“查询失败”，失败时附带具体原因；未找到不是请求失败。本地命中也记录 `local: photo found`，并另行记录使用的本地图片完整路径；上传成功后记录头像更新完成。头像地址命中后，仍需读取或下载并验证图片才能上传。

自动模式只补缺，不主动替换 Emby 已有头像。上传前还会重新读取人物详情，尽量避免覆盖同步期间刚由用户设置的图片；这不构成跨系统的原子锁。

Emby/Jellyfin 的人物资料或头像写入后不再额外刷新人物，避免重新触发外部人物匹配。原“同步后刷新人物”设置已移除；影片发布后的入库扫描通知继续保留。

## 触发与恢复

- 成功发布后合并连续事件，约 5 秒后执行一轮，只处理本次发布影片的演员；失败或回滚的发布不触发。
- Emby 尚未建立本次发布演员的人物记录时，每 5 秒重新检查，最长等待约 5 分钟。各演员从相关发布事件起独立计时，其他演员的发布不会延长其期限；同一演员的新发布事件可重新开始等待。人物出现后只补缺失头像，已有头像保留。期限结束会记录未出现的演员并停止重查。
- 无头像来源、来源查询或上传失败时，不因上述等待机制重复查询头像源或上传；遗漏由下一次相关影片发布、每日定时补查或手动补全处理。每日补查不会自行开启等待循环。单次网络请求仍遵循网络层重试配置，运行中的请求可能超出等待期限。
- MDCz 启动时只恢复未来的定时计划，不立即同步、不补跑停机期间错过的任务，也不再每 30 分钟轮询。每日计划需要开启“自动同步演员头像”，留空时间即可关闭。
- 手动同步会清除本轮来源查询缓存，完成后不额外触发自动检查。
- Emby 认证或上传权限错误会暂停自动上传；保存相关连接设置或手动触发可解除暂停，设置保存本身不发起同步。
- 自动与手动共用任务互斥，任务执行期间新发布的工作会合并保留。关闭页面不终止后台任务。
- 关闭自动同步后停止新增自动调度，已经发出的网络请求可能完成。MDCz 停止运行期间不会继续同步，已上传的 Emby 头像仍保留。

开启自动头像同步时，影片发布始终发送扫描通知，不受独立的“入库后增量刷新目录”开关限制。扫描通知成功仅表示 Emby 接收请求；后台仍以人物记录可用为上传条件。

## 手动补救

人物工具页默认选择 Emby，保留两个模式：

| 模式 | 用途 |
| --- | --- |
| 仅补全缺失头像 / 立即补全头像 | 立即处理遗漏，保留已有头像 |
| 更新全部头像（替换已有） | 用户主动重新获取并替换已有头像 |

任务显示成功、失败、跳过数量，以及可用的失败演员和原因。更新全部头像无法自动还原原图；需要保留手动头像时，先备份 Emby 数据。

## 文件与升级

- 新输出不创建 `.actors`，电影 NFO 不写演员 `<thumb>`，仍保留演员名称、类型和顺序。电影封面、背景图等不变。
- 本地演员头像库仍可作为可选上传来源，它不是 Emby 展示图片时需要访问的共享目录。
- 不再读取旧电影 `.actors` 作为同步来源，也不在资源发布和维护扫描中新增演员头像资产。
- 旧 NFO 和旧头像文件不会被自动批量修改或删除。应先确认 Emby 已保存头像，再通过维护重写选定 NFO 去掉旧引用，最后按需清理旧图片。
- 共享 NFO 输出策略也适用于 Jellyfin；Jellyfin 的人物资料和头像 API 同步入口继续保留。

本次不需要数据库迁移、环境变量或启动命令变更。`emby.autoSyncActorPhotos` 默认 `true`；`emby.actorPhotoDailySyncTime` 默认空字符串，关闭每日补查。未配置 Emby 连接时不会发出自动上传请求。容器部署时请确认服务时区与期望的执行时间一致。升级时旧 `refreshPersonAfterSync` 配置会被忽略，下次保存档案时移除。重建镜像并更新容器后生效；回滚到此次修改前的镜像会恢复单次发布检查和原有刷新行为，若需保留此前的刷新开关值，应一并恢复配置备份。
