# Emby 演员头像自动同步

MDCz 抓取并上传头像，Emby 保存人物主头像。上传完成后，Emby 展示头像不依赖 MDCz 运行、MDCz 缓存或电影目录中的 `.actors`。

## 配置与使用

1. 在“设置 → 媒体服务器 → Emby”填写服务地址、API Key 和必要的用户 ID。凭据需要能够读取人物并上传人物图片；权限不足时页面会显示错误。
2. 保持“自动同步演员头像”开启（默认开启），在“人物头像来源顺序”配置需要的来源。
3. 正常刮削或通过维护功能发布影片。MDCz 会通知 Emby 扫描，后台自动补全缺失头像，无需打开工具页。
4. 通过 Emby 设置中的“查看演员头像同步”进入人物工具页，查看等待入库、同步进度、最近结果和失败原因。

自动模式只补缺，不主动替换 Emby 已有头像。上传前还会重新读取人物详情，尽量避免覆盖同步期间刚由用户设置的图片；这不构成跨系统的原子锁。

## 触发与恢复

- 成功发布后合并连续事件，约 5 秒后开始查询；失败或回滚的发布不触发。
- Emby 尚未建立人物记录时，按 10 秒、30 秒、1 分钟、2 分钟、5 分钟退避查询；已出现的人物先处理。
- MDCz 启动后执行补缺，之后每 30 分钟补查。重启后根据 Emby 的实际头像状态重新发现遗漏，无需持久化待上传队列。
- 无头像来源的演员冷却 6 小时，避免持续请求相同来源；手动同步会清除本轮来源查询缓存和冷却。
- 短暂失败自动重试；Emby 认证或上传权限错误会暂停自动上传，保存相关连接设置或手动重试后重新检查。
- 自动与手动共用任务互斥，任务执行期间新发布的工作会合并保留。关闭页面不终止后台任务。
- 关闭自动同步后停止新增自动调度，已经发出的网络请求可能完成。MDCz 停止运行期间不会继续同步，已上传的 Emby 头像仍保留。

开启自动头像同步时，影片发布始终发送扫描通知，不受独立的“入库后增量刷新目录”开关限制。扫描通知成功仅表示 Emby 接收请求；后台仍以人物记录可用为上传条件。

## 手动补救

人物工具页默认选择 Emby，保留两个模式：

| 模式 | 用途 |
| --- | --- |
| 仅补全缺失头像 / 立即补全头像 | 立即处理遗漏，保留已有头像 |
| 更新全部头像（替换已有） | 用户主动重新获取并替换已有头像 |

任务显示成功、失败、跳过数量，以及可用的失败演员和原因。更新全部头像无法自动还原原图；需要保留手动头像时，先备份 Emby 数据。

## 文件与升级

- 新输出不创建 `.actors`，电影 NFO 不写演员 `<thumb>`，仍保留演员名称、类型和顺序。电影封面、背景图等不变。
- 本地演员头像库仍可作为可选上传来源，它不是 Emby 展示图片时需要访问的共享目录。
- 不再读取旧电影 `.actors` 作为同步来源，也不在资源发布和维护扫描中新增演员头像资产。
- 旧 NFO 和旧头像文件不会被自动批量修改或删除。应先确认 Emby 已保存头像，再通过维护重写选定 NFO 去掉旧引用，最后按需清理旧图片。
- 共享 NFO 输出策略也适用于 Jellyfin；Jellyfin 的人物资料和头像 API 同步入口继续保留。

本次不需要数据库迁移、环境变量或启动命令变更。新增配置项为 `emby.autoSyncActorPhotos`，默认 `true`；未配置 Emby 连接时不会发出自动上传请求。
